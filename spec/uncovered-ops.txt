# Spec operations this SDK deliberately does NOT target.
#
# The operations analogue of the coverage half of spec/schemas.txt. Together with
# endpoints.txt this file must account for EVERY operation in the vendored spec
# (invariant G in scripts/check-spec-drift.mjs), so a spec release that adds an
# operation fails CI until someone either implements it or records here why not.
# Unlike the schema list, 100% operation coverage is not the goal: the spec carries
# admin routes, deprecated routes, and legacy-gateway twins of operations this
# client already reaches through `/api/v1`.
#
# Entries are staleness-checked both ways: a line the spec no longer defines fails
# (drop it), and so does a line that endpoints.txt has since started targeting
# (remove it — it is covered). So this cannot rot into a list of routes that no
# longer exist.
#
# Format matches endpoints.txt: `METHOD /path`, one per line, placeholders as the
# spec spells them.

# ── Legacy-root forms of the funds surface the client sends to /api/v1 ─────────
#
# The client implements each of these, but against its `/api/v1` sibling, which
# the spec does not yet document — so the implemented path sits in CODE_ONLY_OPS
# (see check-spec-drift.mjs) and the documented path sits here. When the spec
# ships the `/api/v1` variants, the CODE_ONLY_OPS entries move into endpoints.txt
# and these lines stay put.
#
# The first two are different: ENG-8463 — `POST /api/v1/account/deposit` and
# `POST /api/v1/account/margin` appear to be routed nowhere, so `deposit()` and
# `adjustMargin()` are probably calling a path that 404s. If that is confirmed,
# the client moves to the bare paths below and these two lines go away.
