# Rule levels this repo decides, rather than inheriting from oasdiff (ENG-14163).
#
# Format: one `<rule-id> <level>` per line. Passed to `oasdiff` as
# `--severity-levels` by `classify_spec_change.py` (ENG-18796), which both the
# `Exchange API Spec` job in pr-required-checks.yml and the interfaces release
# pipeline run.
#
# WHY THE FILE EXISTS. The classifier picks `--fail-on WARN` rather than `ERR`,
# and its comment says why: `ERR` alone would ship a vanished response field under a MINOR
# bump, and "no client-side discipline saves you from that one". The rule carrying
# that case is `response-optional-property-removed`, and the reasoning held while
# the job ran oasdiff 1.10.15, where the rule is `warning`.
#
# It stopped holding without a diff. The install below was `install.sh`, which
# fetches the latest release, and oasdiff has since moved that rule to `info`:
#
#   rule                                 1.10.15    1.30.0
#   response-optional-property-removed   warning    info
#   response-property-enum-value-added   warning    error
#   response-required-property-removed   error      error
#
# So `--fail-on WARN` stopped seeing it. On the real #9638 commit pair (ENG-13314,
# fourteen renamed `Order` fields), 1.10.15 reports `154 breaking changes: 0
# error, 154 warning` and exits 1; 1.30.0 reports `319 changes: 0 error, 0
# warning, 319 info` and exits 0.
#
# Pinning the version stops that from recurring silently. This file is the other
# half: the level a removed response field carries is a decision about our
# contract, so it is recorded here and does not move when upstream re-grades it.
#
# Keep this list SHORT. It is for rules whose level this repo has an argued
# position on, not a place to re-grade oasdiff wholesale.

response-optional-property-removed err
