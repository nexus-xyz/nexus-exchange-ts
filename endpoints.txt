# Operations this SDK targets, checked against the vendored spec (spec/openapi.json,
# pinned by .api-version) by scripts/check-spec-drift.mjs. The check validates the
# list BOTH ways — that is what makes the number here trustworthy rather than a
# hand-maintained claim:
#
#   * every line must exist in the vendored spec (invariant F) — so a removed,
#     renamed, or mis-prefixed operation fails CI rather than quietly overstating
#     coverage;
#   * the set must equal the REST operations src/client.ts actually implements
#     (invariant H), modulo ONE named allowlist in check-spec-drift.mjs:
#       - NON_REST_TARGETS — targeted without a `this.#request(...)` call, so
#         invisible to the code parser: `GET /ws`, opened by src/ws/client.ts.
#
# There is NO allowlist for an operation the spec does not define. An endpoint
# absent from the pinned contract must not be implemented (ENG-8616), so there is
# nowhere to park one: `CODE_ONLY_OPS` in check-spec-drift.mjs is empty and the
# check fails on ANY entry. If the SDK wants an operation the spec lacks, it waits
# for the released tag that defines it — it does not ship the method meanwhile.
#
# Every spec operation NOT listed here must be recorded in spec/uncovered-ops.txt
# (invariant G), so new upstream surface cannot land unnoticed.
#
# So: add a line here whenever you add a client method for a spec operation, or
# the drift check fails. Format, one per line:
#
#   METHOD /path      (placeholders match the spec, e.g. {market_id})
#
# Dual-stack routing (ENG-4947 / gateway elimination ENG-4740): the path here is
# the LOGICAL path — the one the SDK signs, which is the wire path minus whatever
# prefix the deployment base carries (ENG-8463 split the two: the testnet base is
# `https://exchange.nexus.xyz/api/exchange`, and the gateway strips that before
# verifying the HMAC). A method that does not pass `root: true` composes
# `API_BASE_PATH` + its path and is listed with the `/api/v1` prefix; a method
# that does passes it bare and is listed bare. Which of the two a route uses is
# not a style choice — it is whichever spelling the spec declares, since a line
# here that the spec does not define fails invariant F.

# --- Root-relative surface (`root: true`) — market data & venue health ---
# The spec declares these four bare and declares NO `/api/v1` twin of any of
# them — unlike their neighbours in the `/api/v1` market-data block above, which
# it declares both ways. That asymmetry is the contract's, not a preference:
# `root: true` is read off each operation's own spelling (invariant F fails on
# the other one), never off what the routes next to it use.
#
# Two of the four are authenticated (`[{hmacAuth: []}]`, and they document a
# 401): `GET /markets`, whose full market parameters are not part of the public
# summary surface, and `GET /markets/{market_id}/adl-events`. `GET /status` and
# `…/risk-params` are `security: []`.
GET /markets
GET /status
GET /markets/{market_id}/risk-params
GET /markets/{market_id}/adl-events

# --- Root-relative surface (`root: true`) — authenticated account reads ---
